Every candidate is built by `main`'s Release Candidate (`--ref main -f ref=<ref>`, 2.1-M288); the reader release's from the commit that closes Step 2.0.4 (2.1-M70).

A step it cannot read ships its reader first in a further stable reader release on `release/2.0`, whose PR and candidate lane runs read the step's branch output; the step merges into `main` once that tag exists, and the rollback lane and D3 then use it (2.1-M23, 2.1-M68).

## Rules for every phase

- **Opens with a usefulness pass** (2.1-Q75): each feature and seam the phase touches named with its user path, roadmap item, trust boundary or system quality, after checking `docs/plans/hydrology.md`, `onf-plugin-adaptation.md` and `docs/guides/data-library.md`; what has none is deleted, and reachable features with no clear user go to the user as one question.
- **First commit** lands the phase's rules as ratchets of today's sites, each failing on its planted violation (contracts §12, 2.1-M40), and its user-path tests as expected failures. Phase 0 built that machinery (2.1-M69, 2.1-M73). Phase 1's mechanical rename precedes its rules commit, so the ratchets name the final paths (2.1-M346).
- **Closes with** a kept, deleted and asked table; a connections review; the scenario re-walk diff and the agent trials re-run on 2.1-Q264's schedule (none at Phases 0 and 1; ADR 0028); a per-area mutation run over the areas the phase changed, whose survivors become tests or beads; the ratchet numbers; the module and crate diagrams held to the layer table and `Cargo.toml` by `check_docs.py` (2.1-M344); an empty flake quarantine; a retrospective that leaves a rule, script or test; and a Desktop beta on the beta channel (F6, 2.1-M22, 2.1-Q201).
  - Phase 3 closes with a mutation run over the whole Rust workspace instead, once the crates have their 2.1 shape: `exclude_re` for unobservable mutants (`Debug`, `Display`, log text), survivors grouped by function before triage (2.1-Q269).
  - The close also counts CI failures a local check would have caught (target 0, 2.1-Q262); every open bead labelled for the phase is closed or re-slotted with its reason; and the beta's Release Candidate has passed its dry run on the PR that last changed it (canopi-f47t.52.228.61).
- **Streams** are cut by feature and own disjoint files; coupled work is one sequential stream; a stream owns its locale namespace in all 11 locales. This plan names what each stream builds, never which files it holds: file ownership, shared rows and hand-offs between streams go in each step's owners file at its design check ([agentic delivery](../guides/agentic-delivery.md#gates), Ownership; 2.1-M95). The layer table may check the frontend rows but is not the owners file's source.
  - The owners file applies the routing decisions: shared docs edited through the merge agent, who runs `check_docs.py` on the merged text (2.1-M26); ratchet family files shared by concurrent streams (contracts §12, 2.1-M73); the shared native files while the crates split (2.1-M52); a command row first called by a later stream (2.1-M72).
- **A move carries its rewrites** (2.1-M20). The stream that moves or rewrites a module, in the same change: rewrites its tests through public surfaces (F4's ratchets), adopts the failure path in it (Phase 1's adoption ratchets), and rewrites the guide sections, `CONTEXT.md` and AGENTS.md lines it makes stale, within the `check_docs.py` budgets. D1 is a final consistency pass, not the place docs catch up.
  - A path-only move whose area's failure adoption the plan gives a later stream carries only its imports, tests and doc lines (2.1-M65): 2a's `app/data-library/` rename leaves display and the busy regex to N1 and the Site data rows to N3. A moved file's ratchet entries are renamed with it at the same or a lower count (contracts §12, 2.1-M74).
- **Gates** run on the changed area (AGENTS.md), through the tracked hooks in every worktree (2.1-Q266): the pre-commit gate, and from Phase 1's gate rework the pre-push hook running the full Linux mirror (2.1-Q262). The Rust rows run after every crate step. The Web check runs Chromium, WebKit and Firefox (2.1-Q84). Live checks drive an isolated review instance.
- **Exit numbers** read from the ratchet files (contracts §12), each from its family file's baseline at Phase 0's close (2.1-M342) to the number the exit names; a count with no family yet starts from the measurement its stream records at its start. A ratchet only shrinks. A number the phase misses goes to the user with its reason, never into a raised baseline.

## Step 2.0.4: the reader release, before any 2.1 store is written

**Goal for users.** After a rollback from any later 2.1 build, the reader release shows every Design and every store it knows as 2.1 left it, read-only, and changes nothing. It also brings Phase 0's self-update and Phase 1's fixes to stable.

**Why here** (2.1-Q138, 2.1-M21; ADR 0026 Rollback). Release notes name every store and format step and the release a rollback goes to.

**Tests by behaviour.** `check_docs.py` fails on a rule whose check is missing; every port's contract suite passes through both real sides; the rollback test passes.

**Real-environment checks.** Full gates, the Web check and the native live check on the release candidate, updater-signed; the last `2.1.0-beta.<n>` AppImage and `.deb` update themselves to the 2.1.0 release candidate from a staged beta endpoint that lists it, and a reader-release install updates to it from a staged stable endpoint; both are the updater-e2e lane's local server, serving channel files shaped as the release workflow attaches them to GitHub releases (2.1-Q250), since a real `stable.json` is the published release itself.

**Exit (the stopping rule, 2.1-Q3).** All 12 scenarios are re-walked and each touches only its owners within ideal plus 25%; a format bump counts as one owner, the core. No trial score is worse than its baseline. Cross-area edges at or below the Phase 0 target. Every violation entry of a named ratchet, and the jscpd clone count, is empty or carries an open bead; the performance budgets and the coverage exclusion globs stay as standing entries within their tolerance (contracts §12, 2.1-M78).

**At the exit**, this plan and its contracts file are deleted; the ledger stays. 2.1.0 ships updater-signed (Windows code-signed if the SignPath grant exists) and deploys Web (2.1-Q5); then one release per roadmap item.

**User hears.** Any scenario still over its bound, with a costed redesign rather than a patch, and the follow-up beads.
