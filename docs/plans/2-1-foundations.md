## Rules for every phase

- **Opens with a usefulness pass** (2.1-Q75; Phase 0's also weighs each mechanism of ADRs 0022 to 0030 against what it prevents): each feature and seam the phase touches named with its user path, roadmap item, trust boundary or system quality, after checking `docs/plans/hydrology.md`, `onf-plugin-adaptation.md` and `docs/guides/data-library.md`; what has none is deleted, and reachable features with no clear user go to the user as one question.
- **First commit** lands the phase's rules as ratchets of today's sites, each failing on its planted violation (contracts §12, 2.1-M40), and its user-path tests as expected failures. Phase 0 builds that machinery: K lands the format after F0's release sets, each Phase 0 stream's first commit holds its user-path tests as expected failures, and each rule lands so in the F1a, F1b, F2, F3b, F3d or F4 commit that creates its family (2.1-Q141, 2.1-M69, 2.1-M73, 2.1-M186).
- **Closes with** a kept, deleted and asked table; a connections review; the scenario re-walk diff and the agent trials re-run (ADR 0028; runs per task 2.1-Q226); a full per-area mutation run whose survivors become tests or beads; the ratchet numbers; the module and crate diagrams generated from dependency-cruiser and `cargo tree`; an empty flake quarantine; a retrospective that leaves a rule, script or test; and a Desktop beta on the beta channel (F6, 2.1-M22, 2.1-Q201).
- **Streams** are cut by feature and own disjoint files; coupled work is one sequential stream; a stream owns its locale namespace in all 11 locales. This plan names what each stream builds, never which files it holds: file ownership, shared rows and hand-offs between streams go in each step's owners file at its design check ([agentic delivery](../guides/agentic-delivery.md#gates), Ownership; 2.1-M95). The layer table may check the frontend rows but is not the owners file's source.
  - The owners file applies the routing decisions: shared docs edited through the merge agent, who runs `check_docs.py` on the merged text (2.1-M26); ratchet family files shared by concurrent streams (contracts §12, 2.1-M73); the shared native files while the crates split (2.1-M52); a command row first called by a later stream (2.1-M72).
- **A move carries its rewrites** (2.1-M20). The stream that moves or rewrites a module, in the same change: rewrites its tests through public surfaces (F4's ratchets), adopts the failure path in it (Phase 1's adoption ratchets), and rewrites the guide sections, `CONTEXT.md` and AGENTS.md lines it makes stale, within the `check_docs.py` budgets. D1 is a final consistency pass, not the place docs catch up.
  - A path-only move whose area's failure adoption the plan gives a later stream carries only its imports, tests and doc lines (2.1-M65): 2a's `app/data-library/` rename leaves display and the busy regex to N1 and the Site data rows to N3. A moved file's ratchet entries are renamed with it at the same or a lower count (contracts §12, 2.1-M74).
- **Gates** run on the changed area (AGENTS.md), through the pre-commit gate. The Rust rows run after every crate step. The Web check runs Chromium, WebKit and Firefox (2.1-Q84). Live checks drive an isolated review instance.
- **Exit numbers** read from the ratchet files (contracts §12). A ratchet only shrinks. A number the phase misses goes to the user with its reason, never into a raised baseline.

**Q45 findings.** The last review pass's findings (2.1-Q45) sit in the stream lines that fix them, each with its one owner, what is deleted, its test and its exit number; their finding keys and evidence are in the gate-logs. Each one's scope is in the stream's existing bead; the new ones are .52.70 operation id, .52.71 gallery root, .52.72 fault seam and fuzzing, .52.73 command table, .52.74 file grants, .52.75 release version, .52.76 keymap shortcut text, .52.77 geocoding, and the bugs .52.78 to .52.86 (`canopi-f47t.` prefix).
