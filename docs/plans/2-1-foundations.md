- **Closes with** a kept, deleted and asked table; a connections review; the scenario re-walk diff and the agent trials re-run (ADR 0028); a full per-area mutation run whose survivors become tests or beads; the ratchet numbers; the module and crate diagrams generated from dependency-cruiser and `cargo tree`; an empty flake quarantine; a retrospective that leaves a rule, script or test; and a beta build on the beta channel (F6, 2.1-M22).
- **Streams** are cut by feature and own disjoint files; each stream's rows are in the step's owners tsv ([agentic delivery](../guides/agentic-delivery.md#gates), Ownership); the layer table may check the frontend rows but is not the owners file's source. Coupled work is one sequential stream. A stream owns its locale namespace in all 11 locales.
  - A ratchet family file is owned by the stream that creates it; one that more than one concurrent stream lowers is a shared (`*`) row of the owners tsv, each stream editing only its own paths' entries and the merge agent resolving the file at each merge (contracts §12, 2.1-M73).
- **A move carries its rewrites** (2.1-M20). The stream that moves or rewrites a module, in the same change: rewrites its tests through public surfaces (F4's ratchets), adopts the failure path in it (Phase 1's adoption ratchets), and rewrites the guide sections, `CONTEXT.md` and AGENTS.md lines it makes stale, within the `check_docs.py` budgets. D1 is a final consistency pass, not the place docs catch up.
  - A path-only move whose area's failure adoption the plan gives a later stream carries only its imports, tests and doc lines (2.1-M65): 2a's `app/data-library/` rename leaves display and the busy regex to N1 and the Site data rows to N3. A moved file's ratchet entries are renamed with it at the same or a lower count (contracts §12, 2.1-M74).
  - Shared docs (`AGENTS.md`, `CONTEXT.md`, `docs/architecture.md` and any guide two concurrent streams touch) are edited through the merge agent: each stream hands its rewritten lines in its handoff, and the merge agent applies them in the same PR and runs `check_docs.py` on the merged text (2.1-M26).
- **Gates** run on the changed area (AGENTS.md), through the pre-commit gate. The Rust rows run after every crate step. The Web check runs Chromium, WebKit and Firefox (2.1-Q84). Live checks drive an isolated review instance.
- **Exit numbers** read from the ratchet files (contracts §12). A ratchet only shrinks. A number the phase misses goes to the user with its reason, never into a raised baseline.

**Q45 owners** lines name, for each finding of the last review pass, its one owner, what is deleted, its test and its exit number; the finding key is in brackets, and the evidence is in the gate-logs. Each line's scope is in the stream's existing bead; the new ones are .52.70 operation id, .52.71 gallery root, .52.72 fault seam and fuzzing, .52.73 command table, .52.74 file grants, .52.75 release version, .52.76 keymap shortcut text, .52.77 geocoding, and the bugs .52.78 to .52.86 (`canopi-f47t.` prefix).

## Step 2.0.4: the reader release, before any 2.1 store is written

**Goal for users.** After a rollback from any later 2.1 build, the reader release shows every Design and every store it knows as 2.1 left it, read-only, and changes nothing. It also brings Phase 0's self-update and Phase 1's fixes to stable.

**Why here** (2.1-Q138, 2.1-M21). Phase 2's beta is the first published build that writes a 2.1 store form, so its readers must be on stable first. Readers ship one release before writers (2.1-E4): with this release as the previous one, every 2.1 store migrates in place and a rollback by one release reads it, so the new homes, the unwritten old forms and E7's kept copies are dropped, M15 becomes the kept v9 Draft form and M17 narrows to the `settings.before-reset` row (ADR 0026 Rollback).

**Frozen forms.** This step freezes the 2.1 forms it reads, from contracts §7, §10 and §11: `.canopi` v10's read schema (files and Desktop Drafts, 2.1-M31), the IndexedDB Draft record, user DB 10, catalogue 26 (lineage, the `vector` literal, one `lidar_jobs` table for imports and analyses with `operation_id` and the state and outcome CHECKs of contracts §8) and settings record 2, and on Web the species-list record (favourites and recently viewed, contracts §19 ED-25).

It opens any later version of each as `newer-read-only`, reading only the fields, tables and literals it knows and never writing; the rollback lane proves each later step readable, and a step it cannot read ships its reader first, in a further stable reader release (Order constraints, 2.1-M23, 2.1-M32).
