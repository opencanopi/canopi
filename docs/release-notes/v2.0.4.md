# Canopi 2.0.4

From this version, Canopi Desktop updates itself on Windows and Linux. Canopi 2.0.4 also brings the problem reports, notices and fixes tested in the 2.1 betas to everyone, makes the Mac easier to install and to move around in, and gets ready for Canopi 2.1: if you try 2.1 and come back to this version, it shows what 2.1 saved, read-only, and changes nothing.

## Canopi Desktop

### Updates

- On Windows and Linux, Canopi Desktop now updates itself. It checks once at launch (turn this off in Settings › About › Check for updates at launch), or when you choose Help › About Canopi › Check for updates. When a new version is out, a notice offers About, which shows the version and a What's new link; Download and install starts the update. On macOS, About links to projectcanopi.com to download the new version.
- About offers Cancel while an update downloads, and Retry if the download fails. A download that can't be verified offers Check for updates instead.
- On Linux, the AppImage updates in place and the `.deb` asks for your password. If Canopi can't install the update (no password prompt on the system, or the AppImage's folder can't be changed), About links to projectcanopi.com instead. If an install fails, your Design stays open and Canopi says why ("Update not installed: …"); otherwise Canopi saves and restarts into your Design.
- On Windows, Canopi saves your Design, closes while the installer runs and reopens the Design afterwards. If the update doesn't install, Canopi says "Update not installed" at the next launch.
- If you close Canopi while an update installs or finishes, the window says "Installing update…" or "Finishing update…" and closes once the update is done.

### Opening Designs

- Double-clicking a `.canopi` file opens it in Canopi on Windows and on Linux with the `.deb`. With the AppImage or on macOS, open Designs from Canopi.
- Opening a `.canopi` file while Canopi is running opens it in the window you have, after asking about unsaved changes. If you open several at once, Canopi opens the first and says "Canopi opens one Design at a time".
- Show in folder, on a Recent Design or a problem report, opens its folder with the file selected.

### Problem reports

- Help › Report a problem… now saves one zip file on this device, in the Problem reports folder of Canopi's data folder, instead of a folder of files on your Desktop. Nothing is sent: when the report is created, Canopi opens the folder with the zip selected, and Show again opens it again. If you cancel while the report is being written, Canopi still saves the zip there, but doesn't open the folder or show an error.
- Problem reports name the webview version.

### On a Mac

- The Mac app is now signed ad hoc (still without a publisher certificate), so on its first open macOS says it cannot verify Canopi or check it for malware, and System Settings offers Open Anyway, instead of saying the app is damaged (see Before you upgrade).
- If your Mac is too old to run Canopi, the window says "Canopi couldn't start" and asks you to update the operating system, instead of staying empty. Canopi needs macOS 12 or later with Safari 16.4 or later; macOS 12 users get the newer Safari from Software Update.

## Web Edition

- Help › Report a problem… now works in the Web Edition: it downloads one zip file to your browser's downloads, with the open Design if you tick Include current Design. Nothing is sent.
- Closing the tab first saves an edit still being written to your Draft, and asks before closing only while the last save of your Draft failed.
- On tablet-width windows, Download a copy is in File, and the save status no longer covers Open.
- If the browser is too old to run Canopi, the page says "Canopi couldn't start" and asks you to reload, then to update the browser or try another one, instead of staying empty. The Web Edition runs in Safari 16.4, Chrome 111, Edge 111 or Firefox 121 or later.

## Canopi Desktop and Web Edition

### Problem reports

- Under "The report holds", the report dialog lists everything the report includes; your Design is still added only if you tick Include current Design. Copy summary is gone: what you write goes in the zip. The dialog explains how to send the report and links to Canopi's GitHub issues page.
- The report lists recent errors from the app and the last 50 failed background operations, with paths and keys removed. Your Maps key is never included. A failure that repeats is listed once with its count, so it no longer pushes older failures out of the report.
- Report a problem on a saved-data notice, on a panel that failed, or on the whole-window error starts a report that names that failure first.
- If Canopi can't open a Design, a problem report names the field in the file that it refused, without the file's contents. The message on screen stays short.

### Notices and errors

- Notices wait in one row: problems with Canopi's saved data, update notices and the other notices that stay until you act. When several wait, the row shows one at a time with its place in the count ("1 of 3"): the result of what you just did comes first, then the rest, oldest first. A notice stays until you dismiss it or it no longer applies, and a failure that keeps repeating shows its notice once, even after you dismiss it.
- If your settings can't be read, Canopi says so, uses defaults for the session and won't change your saved settings. Try again reads "Trying again…" while it runs, and says so if they still can't be read.
- When Canopi's saved data is damaged and set aside at launch, a notice now says so and names the file it was set aside as. Your Designs are not affected.
- If a panel or dialog fails, it shows "This panel couldn't load" in its place, with Try again and Report a problem; the rest of Canopi keeps working. On the Web, a panel that can't load after a new version was published also offers Reload.
- If the whole window fails, it offers Reload and Report a problem, and no longer shows raw error details. Reload first saves your Design and settings; if they can't be saved, Canopi asks before reloading.
- Messages such as Undo now show above open dialogs, and you can reach Undo with Tab without leaving the dialog.
- Choosing Open, Save or Import while a file dialog is already open no longer shows an error message.

### Moving around the canvas

- On a Mac, a new installation of Canopi Desktop, or a browser that has never run the Web Edition, starts with the pointing device set to Trackpad: two fingers pan, pinch zooms. With a mouse, switch it in Settings › Canvas › Pointing device. Settings you already have are kept.
- The Select tool's hint names Settings › Canvas › Pointing device, and on a Mac it says Option-click removes from the selection.
- The welcome screen has a "Moving around" link that opens Help at its gestures section. On a Mac, Help's gestures name two fingers on the trackpad or the Pan tool for panning, Option-click for removing, and the trackpad twist for turning the view.
- Settings › Files and data says your favorites stay on this computer (Desktop) or in this browser (Web), not in a Design.

### Ready for Canopi 2.1

If you try Canopi 2.1 and come back to 2.0.4, this version shows what 2.1 saved and changes none of it:

- A Design saved by a newer Canopi opens read-only. The save status shows "Read-only"; click it to read why and to choose Update (on Desktop, About checks for updates; on the Web, the page reloads). Close is the only action: no editing, saving, printing or export. Recent Designs and the Draft list label it "Read-only: saved by a newer Canopi", and a Draft this version can't read says so instead.
- Your favorites, saved stamps and recent Designs, your settings and the Data library each show a notice when a newer Canopi saved them. You can view them, but changes aren't saved; changed settings apply until you close Canopi.
- Data library items made by a newer Canopi are listed by name and type with a note to update Canopi; they aren't drawn on the map. Saved stamps from a newer Canopi are listed with the same note and can't be placed, renamed, reordered or deleted.
- In the Web Edition, Drafts saved by 2.1 are listed read-only beside your other Drafts, each with Download a copy, and the old copies 2.1 replaced are hidden; nothing reopens by itself while they exist. Favorites and recently viewed plants saved by 2.1 are shown, but the favorite star is off and recently viewed isn't recorded. If the browser's storage can't be checked, a Draft opens read-only with Download a copy. If 2.1 is opened in another tab, this tab offers Reload.

### Other changes

- About has an Open-source notices link listing the licences of the software Canopi includes.
- Design notebook entries show when they last changed as Recent Designs does: "Today" or "Yesterday" with the time, else the date.
- A Design with nothing in it, saved with a view, reopens at that view, north up, instead of the overview.
- Saved-view thumbnails taken while the map can't load show without the map tiles, instead of waiting several seconds each.
- The map recovers cleanly after the graphics context is lost.
- Plant names and labels drawn before Canopi's font finished loading are drawn again in that font.
- In Russian and the other languages with several plural forms, counts read correctly (3 растения, 5 растений). A saved stamp with no name and no plants is named in your language instead of in English.
- In Chinese, the Calendar's date picker starts its week on Monday. A stored date that doesn't exist, such as 30 February, shows as no date instead of rolling over to March.
- In Russian, the elevation profile's Copy values no longer wraps on phones.
- After you delete the last saved view, focus stays in Manage views.
- Importing several elevation tiles that share one grid no longer drops a row of cells at the item's edge.
- The PDF export retries a font download that times out or that the server fails.

## Security

Canopi Desktop updates:

- tokio to 1.54.1 (RUSTSEC-2026-0386).
- rusqlite to 0.41, which includes SQLite 3.54.1 (RUSTSEC-2026-0459: SQLite before 3.54.0 could return uninitialised memory when it opens a database together with a crafted `-wal` file of a different page size; the files must be on your device and opened by Canopi).
- rustix to 1.1.6 (RUSTSEC-2026-0486: its extended-attribute functions could mark unwritten bytes as initialised when given a zero-length buffer).

## Known limits

- On Linux, if your file manager cannot select a file (it offers no `org.freedesktop.FileManager1`), Show in folder, and a new problem report, open the folder without selecting the file.
- On GNOME with Wayland, opening a second file while Canopi runs may show "Canopi is ready" instead of raising its window: GNOME refuses to bring the window forward. Click the notification or switch to Canopi.
- The known limits of [Canopi 2.0.0](https://github.com/opencanopi/canopi/releases/tag/v2.0.0) still apply.

## Before you upgrade

Canopi 2.0.3 does not update itself: install Canopi Desktop 2.0.4 by hand once, and later versions update themselves on Windows and Linux. Installing 2.0.4 over 2.0.x keeps your Designs, Drafts, Data library and settings, and they still open in 2.0.3. On Windows the MSI installs over 2.0.3's MSI. If you run a 2.1 beta, it updates itself to the next beta, which carries these changes. The Windows installer uses your Windows display language when it is one of Canopi's 11 languages, and English otherwise. On Linux, Canopi needs Ubuntu 22.04, Debian 12 or a newer distribution. On a Mac, Canopi needs macOS 12 or later with Safari 16.4 or later (Software Update offers it). The Web Edition runs in Safari 16.4, Chrome 111, Edge 111 or Firefox 121 or later; open tabs from 2.0.3 keep working.

The installers carry no publisher certificate, so the first open takes one more step. On macOS, open the dmg and drag Canopi to Applications, then open Canopi. If macOS says it cannot verify Canopi or check it for malware, click Done, Cancel or OK (not Move to Trash), open System Settings › Privacy & Security (on macOS 12, System Preferences › Security & Privacy), click Open Anyway beside Canopi and confirm. If macOS says Canopi is damaged, open Terminal, run `xattr -dr com.apple.quarantine /Applications/Canopi.app`, then open Canopi. On Windows, if SmartScreen appears, click More info › Run anyway.

## Source code

Canopi is AGPL-3.0-or-later free software; its installers include the GeoLibre tool, which contains the AGPL-3.0-or-later `wbspatialstats` tools. The complete source of this release is Canopi at tag `v2.0.4` plus the `geolibre-rust` and `whitebox-wasm` revisions in `THIRD_PARTY_NOTICES.md`, linked from the release page.
