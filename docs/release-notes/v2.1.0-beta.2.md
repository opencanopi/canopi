# Canopi 2.1.0 beta 2

The second beta of Canopi 2.1, for Canopi Desktop on Windows, Linux and macOS. This beta changes how Canopi tells you when something goes wrong, and how you report it. The Web Edition gets these changes at the stable 2.1.0 release.

## Problem reports

- Help › Report a problem… now saves one zip file on this device, in the Problem reports folder of Canopi's data folder, instead of a folder of files on your Desktop. Nothing is sent: when the report is created, Canopi opens the folder with the zip selected, and Show again opens it again.
- Under "The report holds", the dialog lists everything the report includes; your Design is still added only if you tick Include current Design. Copy summary is gone: what you write goes in the zip.
- The dialog explains how to send the report and links to Canopi's GitHub issues page (Open the GitHub issues page).
- The report lists recent errors from the app window and the last 50 failed background operations, with paths and keys removed. Your Maps key is never included. A failure that repeats is listed once with its count, so it no longer pushes older failures out of the report.
- Report a problem on a saved-data notice, on a panel that failed, or on the whole-window error starts a report that names that failure first.
- If Canopi can't open a Design, a problem report names the field in the file that it refused, without the file's contents. The message on screen stays short.
- If you cancel while the report is being written, Canopi still saves the zip in the Problem reports folder, but doesn't open the folder or show an error.

## Notices and errors

- Notices wait in one row at the foot of the window: problems with Canopi's saved data, update notices, "Update not installed" and "Canopi opens one Design at a time". When several wait, the row shows one at a time with its place in the count ("1 of 3"): the result of what you just did comes first, then the rest, oldest first. A notice stays until you dismiss it or it no longer applies.
- The update notice from the launch check stays until you dismiss it or install the update; opening About from it no longer dismisses it. Dismissed, it shows again at the next launch.
- A failure that keeps repeating shows its notice once, even after you dismiss it.
- If your settings can't be read, Canopi says so: "Your settings couldn't be read. Canopi is using defaults and won't change your saved settings this session." Try again reads "Trying again…" while it runs, and says "Your settings still couldn't be read." if they still can't be read.
- When Canopi's saved data is damaged and set aside at launch, a notice now says so and names the file it was set aside as. Your Designs are not affected.
- If a panel or dialog fails, it shows "This panel couldn't load" in its place, with Try again and Report a problem; the rest of Canopi keeps working.
- If the whole window fails, it offers Reload and Report a problem, and no longer shows raw error details. Reload first saves your Design and settings as closing does; if your Design or settings can't be saved, Canopi asks before reloading: Retry, Reload without saving (Reload anyway for settings), or Cancel.
- Messages such as Undo now show above open dialogs, and you can reach Undo with Tab without leaving the dialog. The notice row can't be reached while a dialog is open.
- Choosing Open, Save or Import while a file dialog is already open no longer shows an error message. On Windows and macOS the open dialog comes forward; on Linux, Canopi's window does.

## Data library

- If the Data library list can't be refreshed, the list keeps its last rows, says "The Data library list couldn't be refreshed" and offers Try again. The notice goes away by itself once the list refreshes.
- When you cancel an import and Canopi removes it, "Import cancelled" shows briefly. An import cancelled while it is being prepared is now removed instead of showing as Failed.

## Other changes

- Design notebook entries show when they last changed as Recent Designs does: "Today" or "Yesterday" with the time, else the date.
- A Design with nothing in it, saved with a view, reopens at that view, north up, instead of the overview.
- Plant names and labels drawn before Canopi's font finished loading are drawn again in that font. In Russian, the measurement shown while you draw uses Canopi's font too.
- In Chinese, the Calendar's date picker starts its week on Monday, like the Calendar. A stored date that doesn't exist, such as 30 February, shows as no date instead of rolling over to March.
- In Russian and the other languages with several plural forms, counts read correctly (3 растения, 5 растений), for example in Saved stamps and the PDF page preview.
- A saved stamp with no name and no plants is named by its zone and annotation counts in your language instead of in English.
- After you delete the last saved view, focus stays in Manage views.
- rusqlite is updated to 0.41, which includes SQLite 3.54.1 (RUSTSEC-2026-0459: SQLite before 3.54.0 could return uninitialised memory when it opens a database together with a crafted `-wal` file of a different page size; the files must be on your device and opened by Canopi).
- rustix is updated to 1.1.6 (RUSTSEC-2026-0486: its extended-attribute functions could mark unwritten bytes as initialised when given a zero-length buffer).

## Known limits

- On Linux, if your file manager cannot select a file (it offers no `org.freedesktop.FileManager1`), Show in folder, and a new problem report, open the folder without selecting the file.
- On GNOME with Wayland, opening a second file while Canopi runs may show "Canopi is ready" instead of raising its window: GNOME refuses to bring the window forward. Click the notification or switch to Canopi.

## Before you install

If you run 2.1.0 beta 1, Canopi updates itself to this beta: wait for the notice at launch, or choose Help › About Canopi › Check for updates. On macOS, About links to projectcanopi.com to download it.

Canopi 2.0 does not update itself: install this beta by hand once. It keeps your Designs, Drafts, Data library and settings. On Windows the beta comes as the setup `.exe` only; if you installed 2.0.3 with the MSI, uninstall it first. A Design saved by the beta still opens in Canopi 2.0. The Windows installer uses your Windows display language when it is one of Canopi's 11 languages, and English otherwise. On Linux, Canopi needs Ubuntu 22.04, Debian 12 or a newer distribution.

The installers are not signed yet. On macOS (12 or later), open Canopi once, then go to System Settings › Privacy & Security › Open Anyway; if macOS says the app is damaged, run `xattr -dr com.apple.quarantine /Applications/Canopi.app` in Terminal. On Windows, if SmartScreen appears, click More info › Run anyway.

## Source code

Canopi is AGPL-3.0-or-later free software; its installers include the GeoLibre tool, which contains the AGPL-3.0-or-later `wbspatialstats` tools. The complete source of this release is Canopi at tag `v2.1.0-beta.2` plus the `geolibre-rust` and `whitebox-wasm` revisions in `THIRD_PARTY_NOTICES.md`, linked from the release page.
