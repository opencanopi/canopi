# Ownership and lifecycle

Status: Accepted (2026-10-16, Canopi 2.1 target; built by the 2.1 foundation phases); amended 2026-10-17 (Q34, Q38 to Q41, Q45 pass; the Session-core, settings and job-runner prototypes; ledger 2.1-Q61, 2.1-Q66 to 2.1-Q68, 2.1-Q80, 2.1-Q125, 2.1-Q135, 2.1-E6, 2.1-M6, 2.1-M21); amended 2026-10-19 (the ecosystem review: 2.1-Q144, 2.1-M55, 2.1-M56, 2.1-M63; compound history entries: 2.1-M89); the Desktop window state's owner: 2.1-M135; amended 2026-10-22 (update install order: 2.1-Q233, 2.1-Q234); amended 2026-10-29 (update exits: 2.1-Q254, 2.1-M321)

## Context

In 2.0 nothing owns a Design's scope: about 30 modules watch `sessionIdentity` to reset themselves, and seven start effects at import time that are never disposed. Dirty state is three counters in two halves. The tool has three copies. The canvas host and the map lifetime are separate, and four modules decide style readiness. Drawing reads process globals. LiDAR jobs wait on a polled single-slot lease, and three code paths free library files by three rules.

## Decision

Every domain noun has one owner, written states and a closed list of writers (the concept map in `CONTEXT.md`). Every long-lived thing has one owner, a written state machine and one cleanup rule:

| Thing | Owner | Type (home) | States | Cleanup rule |
|---|---|---|---|---|
| App scope | the edition root, through `installAppLifetime(ports)` | none | live, disposed | app-lifetime effects register here and dispose in reverse order; one `latest()` request guard per controller publishes only the newest request |
| Close and hide | the Session core, fed by the app-lifecycle port | `LifecycleEvent` (`platform/app-lifecycle.ts`) | close requested, hidden (`visibilitychange` to hidden; `pagehide` repeats it), focus lost (Desktop `WindowEvent::Focused(false)`, minimise included), shown{persisted}, store version change, `release-waiting{source: manifest, service-worker, kill-switch, store-newer}` (Web) | close requested: flush the Design, then settings, then drain native (Desktop) or close each IndexedDB connection (Web); hidden or focus lost: flush the Design, then settings, nothing more; `pagehide`: the hidden flush, then close each IndexedDB connection after its transaction; release-waiting: the core shows the one "New version: Reload" notice, flushes on Reload, then calls `applyRelease()` (2.1-M98); Desktop asks first while a job runs (2.1-Q61); adapters never act on page events themselves; the Desktop adapter prevents the close, calls `core.close()` without awaiting it and destroys the window on the session's closing-to-idle edge (2.1-M162). The Desktop adapter turns `WindowEvent::CloseRequested` and `RunEvent::ExitRequested` into the one close request, and so does an update install before the installer starts, since the Windows installer launch exits the process, and so does the macOS updater relaunch (2.1-M97) (2.1-M55; before this core exists, the install goes through today's close guard, 2.1-M63); macOS-specific Quit paths wait for the user's macOS decision; the dmg keeps today's behaviour (2.1-Q125, 2.1-Q135); Linux writes the AppImage beside the running one and renames it over it before the close request, then runs the bounded write drain (2 s) and restarts with the Design path, so a failed install keeps the Design open, and a window close during a Linux install waits for it showing "Installing update…", then closes without restarting (2.1-Q254); on Windows, Canopi, not the plugin, runs the bounded write drain and then starts the installer with the relaunch arguments, so the updated Canopi reopens the Design open at install time (nothing for a Draft); a Windows install that fails after exit shows "Update not installed" at the next launch, and drained jobs show Run again (2.1-Q233, 2.1-Q234, 2.1-M209, 2.1-M321) |
| Design Session | the Session core | `DesignSessionState`, `SaveState` (Session core) | `idle`, `opening{source, current?}`, `open{design}`, `replacing{current, next, question?}`, `closing{current, question?}`, `disposed`; `design = {scope, home, rev, ackRev, save, scene: attached or detached{fields}, migratedFrom}`; `save = idle, pending, writing{rev}, busy, failed, refused, conflict, quota, copy_blocked` | one write lane per Design; replace and close await it; a question is state answered by `core.answer(id, choice)`, a stale id answering `stale`; `dispose()` supersedes pending opens and closes and starts no write (2.1-M162); dispose runs synchronously after the write that acknowledged the last rev; `current` stays open and saveable in every transition (2.1-Q66); a home write is a compare-and-write on its `HomeVersion` (SHA-256 of the canonical bytes, 2.1-M156) on both editions, so a Draft changed by another tab or an outside writer enters conflict (2.1-Q165) |

| Last open home | the Session core | `LastOpenHome` (Session core) | a home key or none | set when a Design reaches open, cleared on Close, unchanged by quit; `launchIntent()` reads it after any file argument; a gone or unreadable home shows the start screen and clears it; Desktop keeps the path in the user DB, Web a browser record; never a grant id |
| Canvas surface | `app/canvas-map-surface/canvas-host.ts` | `CanvasSurfaceState` | idle, starting, unavailable{cause}, map{map, retry: offered, withheld or never}, releasing; computed by `composeSurface(lease, map)` from the lease (free, held, releasing) | the host is the only writer of the lease and the only caller of `createMapLifetime` and `release`; release order: `core.detachScene()` synchronously, observer, settings flush, composition dispose, unpublish; Retry is offered only for a failed map whose cleanup settled with the runtime alive |

| ToolHost | the interaction session's `_tool` | `ToolHostState` (`_tool`) | one typed state record of reducer sections | a fault aborts open edits and is reported (ADR 0025) |
| Renderer snapshot | the scene runtime | none | self-contained per frame | no process globals |
| Settings store | `app/settings/` | `SettingsStoreState` (`app/settings/`) | loading; ready (notice: fields-reset or write-failed); degraded (refused-newer, newer-read-only or unavailable) | flush and drop on dispose; reading never writes; a degraded store is never written (2.1-Q67); a newer-read-only record applies its known fields (ADR 0026); the window state is not a settings field (2.1-M135); coalescing persistence holds no value: a dirty bit, one run in flight reading the current settings, a failure blocking retries until the next patch or flush |

- **One Undo order** (2.1-Q80). The Session core owns the one Design history: each entry has a stable `HistoryEntryId` and replays its Scene command or Document inverse through its owner; a compound's Document half comes from its Scene half's id remap, refused before commit (2.1-M89, 2.1-M158); selection publishes at commit; toasts show `newestUndoable` (2.1-M159); a new edit ends the redo branch; Undo goes first to the active tool's transient; a detach drops entries holding a Scene token. **Dirty is `rev > ackRev`** (2.1-Q68): only `changed()` advances `rev`; only `written` sets `ackRev`.
- **Surface lifetime.** One module owns the map-lifetime union and hands one style-readiness signal to every contribution; layer and raster status derive from it. The snapshot map goes through the same factory and lifetime.
- **Tool owner.** `_tool` is the only owner of the active tool and its armed source; app code arms only through `armCanvasTool` (ADR 0020), the only caller of `tools.arm(id, source, request?)`, whose optional map input request settles once (picked, cancelled, detached); a drop arms inside the runtime. Each tool has one row in the command table (id, title key, how it is armed, edition capability, static chrome categories); behaviour only the ToolHost runs lives on the tool. A tool picked while no Design is open is dropped (Q41).
- **Renderer snapshot.** Plant display, backdrop ink, paint tokens and the annotation font epoch are part of the snapshot; each surface (workspace, thumbnails, overview, story, lens, print) renders from its own.
- **Settings own their signals** (Q45). `app/settings/` owns every settings-backed signal except the active locale, which `i18n/` owns and settings sets through `setActiveLocale()` (the multi-writer rule counts an owner's setter as an owner write); a slice is the unit features patch (`patchSettings`), several features may patch one slice, and a policy on the patch call says which feature patches which field.
  - One field table in `canopi-types` (key, default, range, slice, capability (optional, an `EditionCapability`; a field without one exists on both editions, ADR 0030), privacy of secret, reported or omitted) generates the TS draft, normalisers, apply, serialise, the browser reader, the Rust `Debug`, the report's settings section and, from its declared steps, both editions' migration runners (2.1-E6, 2.1-M138). A bad value resets only that field (ADR 0026). The Desktop boot read has a reserved slot that Busy never rejects.
- **Library jobs.** The job runner owns admission to the Job lane: one FIFO with a heavy slot for imports and analyses (U32) and a display slot. A job that never started, or was stopped by the quit drain, settles Interrupted with Run again (Q38, 2.1-Q61); a cancelled import is withdrawn (user 2026-10-09). `CancelToken` carries User, Superseded or Shutdown. Facade calls wait for open recovery and the janitor's open run; if recovery fails or the runner stops, the library is read-only (`runner_stopped`) and drain treats the runner as done.
  - State changes are a revision watch plus a re-read, which cancel, Delete, Dismiss and the janitor wait on. They reach the frontend, progress included, through one `tauri::ipc::Channel` subscription per caller that sends the current state on subscribe and then each change in order (2.1-M56); no polls, no broadcast events.
- **Library file rule.** Every writer, and Delete and Dismiss (Q39), records its claim before its first write. Delete of an item a queued or running job reads is refused, naming the job. The janitor is the only module that deletes a library file, only what no claim covers, rows before files; it runs after each settle, Delete and Dismiss and once after open recovery. Design-write sidecars have a recognisable name and are swept only beside their target on its next save; user folders are never walked.
- **Display preparation** runs in the runner's display slot on the Job lane, outside the heavy slot, with no deadline or Busy; requests per key coalesce; its recipe is the analysis row's; its state (preparing, ready, failed with a typed reason) is library state on the same Channel, with no status read and no poll; the frontend's back-off, busy regex and call cap are deleted.
- **Write vocabulary** (2.1-M111): admission is the `.canopi` check only; the write lane is the Session core's serial writes per Design; the target lock makes a `publish_durably` precondition and its publish one step; Busy is executor capacity.

## Alternatives rejected

- **"Adopt a Design scope only if it removes reset code."** About 30 hand-written resets already exist.
- **Reference counting for library files.** It can delete a referenced file when the counts drift.
- **A lossy event broadcast for job state.** A dropped settle event hangs the waiter (job-runner prototype).
- **An old-epoch refusal for writes.** The per-Design write lane makes it unnecessary.

## Checks

- ast-grep `no-module-effect` and `no-session-identity-watch` (to be created by Phase 0, ratchets 7 and 30 files to 0 at Phase 2's close); `no-renderer-module-state` (ratchet from Phase 0, 0 at Phase 2c), widened to `maplibre/` and `app/`; `style-load-only-in-map-lifetime` and `map-constructor-only-in-factory` (ratchets from Phase 0, 0 at Phase 2d); `janitor-only-deletes` (ratchet from Phase 0, 0 at Phase 3).
- A model-based test for each machine with interleavings (ADR 0028), including an edit during an in-flight write, a same-home reopen, quit while a job runs and recovery before the open sweep; a property test interleaving a sweep with each writer kind.
- A ToolHost owner test (created at Phase 2c's start, 2.1-M77); a policy that lease and publish happen only in `app/canvas-map-surface/canvas-host.ts` and `data-map-active` only from the map-surface visibility (Phase 2b).
- dependency-cruiser `settings-no-upward` (Phase 2e) and ast-grep `patch-settings-only-in-field-owners` (ratchet from Phase 0, 0 at Phase 2e); a model test that no write reaches a degraded store (Phase 1b).
- `plant-highlight-only-in-canvas` (ast-grep) and the panel read rules (`planning-panels-import-no-authorities`, `tool-rail-imports-no-canvas-state`): panels read the canvas by read-only queries; only the canvas draws highlights.
