# Failure model and native scheduling

Status: Accepted (2026-10-16, Canopi 2.1 target; built by the 2.1 foundation phases); amended 2026-10-17 (Q34 format core failures, Q47 operation id, Q45 pass; the job-runner prototype; ledger 2.1-Q60, 2.1-Q86, 2.1-M6)

## Context

In 2.0 about 69 commands return `Result<_, String>`. The frontend recognises busy and cancelled by matching English text. The executor refuses work at once when a class is full. Most errors reach only the console, logged below the log filter, so a problem report can miss the failure that prompted it. Paths and Design names are formatted into error text where they are made, so privacy rests on a scrubber. The user decided how native work is scheduled when it is busy (Q21), the failure behaviours users see (Q20, Q22, Q23), one notice row (2.1-Q86) and a problem report on Web (2.1-Q60).

## Decision

- **One failure catalogue** in `canopi-types`, generated to TS. Each code is tagged by one source; the sources and starting codes are listed in contracts §2. Rust errors and the browser adapters produce these codes. One code to locale-key map and one `reportFailure` sink serve both editions.
- **A failure carries** `code`, `user_may_retry`, `op`, `operation` (Q47) and `detail`. `user_may_retry` means only that the screen may offer Retry; nothing retries on its own. `detail` is redacted English for logs and reports and is never shown. An internal guard gets a code only where it reaches the user or a report.
- **The executor owns scheduling** (Q21). It lives in `canopi-support`, which owns the lanes (the request lanes and the Job lane), `OpSpec`, `CancelToken`, priority, deadlines, settlement logging and the private `blocking::run`; it owns no slot primitive and never names a job or a service crate.
  - Each request lane (Catalog, UserData, Library, Local, Network) is a bounded queue. An enqueue onto a full queue waits for a slot until its deadline.
  - The Job lane is an ordinary lane-table row (2 workers, queue bound 2, `Deadline::Unbounded`, its `inner_parallelism` for heavy engines). The job runner in `canopi-library` (ADR 0024) owns admission to it: its heavy and display slots, the jobs table as the visible unbounded queue and per-key display coalescing. A job facade writes its Queued row through an ordinary Library-lane `OpSpec` and returns the `JobId`.
  - A request gets a deadline when it is queued (`Deadline::Unbounded` only for system work: runner transitions, the janitor, the reserved settings boot read) and a priority: interactive reads before background work.
  - Each facade operation declares its lane, priority and deadline once, as its `OpSpec` (ADR 0023); the command map never restates it and has no retry column.
  - Typed `Busy{lane}` is returned only when a deadline expires; long work is a visible Queued job instead. The executor returns typed errors (Busy, Unavailable, Panicked, JoinFailed), never a `String`.
  - A `CancelToken` carrying its reason (User, Superseded or Shutdown) replaces the `check_cancel` copies, the cancel flags and `Err("cancelled")`; `cancel(operation)`, an `OpSpec` `supersede_key` and drain cancel it (contracts §3).
- **The frontend sends one invoke per action and command, and never retries;** a fan-out becomes one command over a list. `ipc/` stays transport: it records a rejected invoke as one `failures/` ring entry per settlement, which a later `reportFailure` marks surfaced instead of adding a second, and returns the typed `Result`; the caller decides what the user sees. Continuous Save treats Busy as "not saved yet" with no client loop. A screen shows Busy once.
- **Logs.** A redacting JSON `tracing` layer writes `op, operation, lane, settlement, code, queued_ms, running_ms, slow`, and `job_id, item_id` for a job. Success logs at debug, busy and cancelled at info, errors at warn, panics at error through one panic hook. Fourteen daily files are kept. The Maps key, location readings and Design content are never logged.
- **User content is typed, not formatted.** Paths, Design names, item names and query text travel as `Sensitive<T>` fields (`UserPath` for paths) of a failure, log event or job message, never inside its text. The log layer writes them redacted; only the problem report renders them, by consent. A secret settings field is `Redacted<String>` in Rust, read only through `expose()`, and its redaction entries, report line and export exclusion are generated from the field table.
- **Redaction** is the second line: each language redacts the text it produces, once; named folders are Rust-only (`canopi-redact`); shared shapes are bound by a tagged corpus; `RedactedText` marks redacted text across the seam. Rust and TS share the credential parameter names and replacement tokens, one table emitted by `bindings-gen`. The one TS redactor is `failures/redact.ts`; `maplibre/redact-credentials.ts` is deleted.
- **A problem report carries** every section, even when empty: the build; subsystem health at report time with causes; queue depths, wait times and the oldest running op; the last 50 native error settlements; the frontend ring with rejected invokes and window errors; job counts and recent failures; library disk use and janitor state; the log tail; a settings summary generated from the settings field table's privacy column (ADR 0024).
  - A report opened from a failure carries its code. One `REPORT_SECTIONS` table in `canopi-types` (id, file, consent, privacy line, editions) feeds one TS builder in `app/problem-report/` on both editions; Desktop returns its native sections already redacted, and a section the edition lacks is marked so in the manifest (2.1-Q60). Nothing leaves the machine unless the user sends it (2.1-Q74).
- **Frontend sinks.** `reportFailure` is the only sink, with window error hooks installed once by `installAppLifetime` (ADR 0024). Each surface has an error boundary with Retry. `reportFailure` sits in L1 `failures/` (ADR 0022), so canvas faults call it directly, with no port; it feeds diagnostics and shows a notice when work or drawing was lost. `failures/` owns the frontend diagnostics ring and a read-only notice signal that a surface renders; Phase 1 stream 1b moves the ring out of `app/problem-report/diagnostics.ts`, and the problem report reads it there.
- **One operation id** (Q47). `OperationId` in `canopi-types` is minted once per user action, by the command dispatcher, a ToolHost commit or a panel submit; system work (a save tick, the janitor, open recovery) mints its own with origin `system`. It is a required argument of every invoke and is stored in the settlement log, the job row, the failure, the ring and the report. An invoke is identified by its settlement event; `OperationId` is the only correlation id that leaves a transport, and transport sequence numbers stay private.
- **Health speaks the catalogue.** `SubsystemHealth` maps a closed `StoreId` set to `{status, notice?}` (contracts §11); a status carries catalogue payloads (a library not ready is `library_read_only{reason}`), changes after boot reach the one health model in `failures/`, and one presentation module over the code-to-key map gives each status its tone and message.
- **Failures users see.**
  - One in-app notice row on both editions shows refusals and results; Desktop opens no native message dialog for a refused file or a GeoJSON result (2.1-Q86).
  - A close whose Design flush fails asks Retry / Close without saving / Cancel (ADR 0009).
  - Closing with an unsaveable settings store flushes the Design first. The session question dialog then asks Retry, Close anyway or Cancel (Q20, 2.1-Q182).
  - Web shows a leave prompt only while the last Draft write failed or a flush is pending (Q22). iOS Safari shows no leave prompt (it fires no `beforeunload` that can prompt); there the save status error and Download a copy are the protection. The leave-prompt e2e runs in the desktop engines; the iOS smoke asserts the error state.
  - A damaged user DB is set aside and the user is told once, with the set-aside file named (Q23).
- **Format core failures** (Q34, 2.1-M154). The adapter maps each to a typed failure; nothing is retried silently and each is reported once. It compiles the `WebAssembly.Module` once at boot and posts it to every respawned or recycled worker, so neither fetches again; a recycle waits until the worker is idle. Every call settles exactly once.
  - A failed load settles `format_core_unavailable`. Load-failed is left only by a user action (Retry, New, Open), which tries one load. New, Open and the Draft list are then unavailable, with one notice that names the format core, not a file. Mid-session, the open Design stays in memory, its save status is error ("not saved yet", Retry) and the leave prompt is armed.
  - A trap settles `format_core_trapped` with the panic hook's message in `detail`, or `trapped` for an out-of-memory abort, which runs no hook. Calls queued behind it settle `format_core_trapped` without running, never replayed. The worker is then terminated and respawned, because a trapped instance stays dead. An encode trap puts the save status in error with Retry and stops automatic save ticks until the next edit or Retry.
  - A write refused by admission is a save error naming the field; nothing is written.

## Alternatives rejected

- **Fail-fast admission with one retry in the IPC transport.** It hides contention behind client retries, puts retry rules in a column of the command map, and the user chose native scheduling instead.
- **Typed Busy with no queue.** Users would see "busy" whenever two calls meet.
- **Queue every call with no deadline.** A stalled share or job would hang screens silently.
- **Native-only error codes.** Web failures would stay English text outside the locale map and the report.

## Consequences

- Executor lanes, priorities, deadlines, the cancel token, the job runner's Queued state and the janitor's background priority are one coupled seam. They land as one sequential stream. Phase 1 adds only the typed failure codes, so no interim fail-fast or poll path is built and then replaced.
- Blocking work runs only through one private `blocking::run` in `canopi-support`, reached by the lanes; the runner spawns no thread, blocking task or detached async task. It is the one listed escape in `BLOCKING_ESCAPE_ALLOWLIST`, and the escape audit scans the `src/` of every workspace crate (Phase 3 N1).
- The frontend busy regex, the plant-DB error prefix matcher and every text match on native errors are deleted.

## Checks

- `native_call_contract` (to be created by Phase 3 N1, with its shared fixtures), a Rust suite on tokio paused time (a running blocking task stops auto-advance, so tests call `advance`): queues are bounded, interactive work goes first, Busy comes only on deadline expiry, long work shows as Queued, and every request settles exactly once; N concurrent requests under one `OperationId` give N settlement events.
- `ipc/transport.test.ts` (one invoke per action, no retry; shared-fixture cases added by Phase 3 N1) and a policy test that every L4 surface has an error boundary (to be created by Phase 1).
- `every_code_reaches_the_report` and `problem_report_always_carries_every_section` (to be created by Phase 1); `problem-report-diagnostics.test.ts`, `map-error-redaction.test.ts` and `settings-sections.test.tsx` (exist).
- One tagged redaction corpus (`canopi-types/fixtures/redaction/`, shared and native-only cases), run by Rust and TS, plus idempotence and survivor property tests (to be created by Phase 1).
- Format core failure e2e through the real worker in Chromium, WebKit, Firefox and the Desktop webview (to be created by Phase 2b): the `.wasm` blocked at boot and a failed instantiation at a respawn (New, Open and the Draft list unavailable; an open Design kept in memory), a trap probe with calls queued behind it, an encode trap that stops save ticks, and an allocation probe.
- ast-grep `no-string-error-command` (widened to `From<String>` impls), `no-cancelled-literal` (both languages), `console-only-in-sink`, `no-user-content-in-message` (a planned row until 1a lands Sensitive<T> and UserPath) and `notice-only-in-failures` (Tauri `message` banned) (to be created by Phase 0, as shrink-only ratchets); the redaction corpus gains every path shape (each OS root, URL and encoded forms).
