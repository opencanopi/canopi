# Architecture fitness and verification

Status: Accepted (2026-10-16, Canopi 2.1 target; built by the 2.1 foundation phases); amended 2026-10-17 (Q47, Q45 pass; enforcement first: ledger 2.1-Q75, 2.1-E2, 2.1-E3, 2.1-M14; a move carries its rewrites: 2.1-M20; the durable-files seam in 2b: 2.1-M28); amended 2026-10-19 (the ecosystem review: 2.1-Q141, 2.1-Q142, 2.1-M57, 2.1-M58, 2.1-M60, 2.1-M67); amended 2026-10-19 (scenario walk 12: 2.1-Q148, 2.1-M92); amended 2026-10-22 (the Phase 0 design check: 2.1-Q200, 2.1-Q213 to 2.1-Q226, 2.1-M186 to 2.1-M200, 2.1-M202, 2.1-M217)

## Context

In 2.0 the policy tests hold boundaries through tombstones, phase-named lists and source-text pins, and many tests read private fields. Several state machines have no sequence test, though canopi-ana9 was a sequence bug. Mutation testing never runs in CI and the LiDAR oracle lane runs on one machine. Of the 259 rules the docs state, 34 code rules have no check and 24 are process rules held only by prose; agents copy the nearest example, trust gate output and invent names. The user set the stopping rule (2.1-Q3), the verification tools (2.1-Q13 to 2.1-Q19) and enforcement first (2.1-Q75).

## Decision

- **Stopping rule** (2.1-Q3). All 12 scenarios (the twelfth, sunlight, from 2.1-Q148 and 2.1-M92, its owners counted by 2.1-M170) are re-walked; each touches only its owners, within the ideal count plus 25%, from a checked-in owner fixture per scenario; a cross-area edge target is fixed at Phase 0 close. A cross-area edge is an ordered pair of areas (a `layers.json` area or a crate) with at least one runtime import, type-only excluded, or a cargo dependency; the target is the measured count minus the edges Phases 2 and 3 name, each a named entry (2.1-M200).
  - The agent change trials (`scripts/agent_trials/`: eight roadmap and maintenance tasks, run by fresh agents with no plan context, scored as the median for files read and changed, owners touched, gate failures before green, wrong-owner edits and violations caught only by review, all but the last computed by `score.py`) re-run at every phase close.
  - They are compared with a baseline of three runs per task on Phase 0's upgraded toolchain: three runs per task at Phases 0 and 4, one at Phases 1 to 3 with three reruns of any task that gets worse (2.1-Q226). Both are read as diffs at each phase close; at Phase 4 every scenario passes and no trial score is worse than its baseline.
- **The policy inventory** (`policy/inventory.json`, Phase 0 F1b) lists every rule the ADRs, guides and AGENTS.md state, with its check or the mark advice or process. Every check has a planted violation that must fail; a rule naming a check that does not exist fails `check_docs.py`. A failure message names the rule, its ADR, the owner and a canonical example module.
- **Primitive ownership.** Each raw primitive a second copy would use (Tauri, MapLibre and Pixi constructors and classes, storage, workers, ids, dates, numbers and units, SQL, hashes, time, HTTP, child processes, durable writes, `sessionIdentity` and lineage reads) has one owner and one rule, landed in Phase 0 as a ratchet of today's sites, but those with no Phase 0 site, which land with their owner (the source table `policy/primitives.json`; 2.1-M77, 2.1-M149, 2.1-M189). It is the main defence against semantic copies.
- **Agent enforcement** (2.1-M14). Claude Code hooks and a pre-commit gate, tracked in `.githooks/` and set through `core.hooksPath`, run the affected checks and the ratchets on every commit, for the user too, with a fast path for docs and bead commits (2.1-Q223); PreToolUse hooks refuse `--no-verify` and hooksPath overrides, a SessionStart hook warns on a worktree without the hooks (2.1-M196), and CI runs the same gate over every commit of a PR, so a bypassed or missing hook fails the PR.
  - A ratchet exception or raised baseline is refused unless its bead is open and its ledger id is a Q row present on the PR's merge base (2.1-M195). A new ratchet family's first baseline, today's sites with its planted violation failing, lands in the commit that creates the family and names the family's ledger row (2.1-M40). An entry renamed with its file in the same commit, at the same or a lower count, is a rename, not an added entry (2.1-M74).
  - A guard refuses a commit that deletes a test unless the commit adds a test whose title it quotes (one per deleted test, with no fewer assertions), cites a Q row, or carries `Retires-test: <title> — <why no user sees it>` and deletes the code under test (2.1-M282); a removed or loosened `expect` in a kept test needs the same, a whole-value equality replacing membership asserts on the same value being no loosening (2.1-M283). A moved test passes; a reworded one passes with `Rewords-test: <old> -> <new>` (2.1-Q224).
  - Gates are deterministic and isolated: fixed seeds, fake clocks, a per-worktree cargo target, e2e in a container on its own network at the default ports (2.1-M287), the affected set computed from the dependency graph.
- **Ratchets only shrink:** layer-order sites, feature SCCs, deep imports, signal writes outside their owner (multi-writer signals included, 2.1-M233), exceptions, String-error commands, Rust SCCs, primitive sites, inline suppressions (2.1-M187), file size over 600 lines (all tracked source with tests; generated files and data fixtures exempt, 2.1-Q214), clones, complexity, quarantined flakes and performance budgets (ADR 0029).
- **Generated rules** (Q13). Policy tables stay data and generate the dependency-cruiser and ast-grep configs. A fail-closed checker refuses a missing source, path drift, an unused exemption and a missing required rule. A policy kind confines `patchSettings(slice, {field})` callers to the field's patching features. Tombstones, phase-named lists, wiring pins and source-text pins are retired.
  - Tool output is normalised into the ratchet files, never a second rule home: dependency-cruiser's `--baseline` and `--ignore-known` output, oxlint's JSON as per-file entries, clippy's item-level `#[expect]` counts and the stricter tsc flags per file (2.1-M58, 2.1-M188). The affected gate's set comes from dependency-cruiser's `--reaches` over the changed modules on the Web graph, plus `vitest related`, and the pre-commit gate runs no cruise (2.1-M284); each rule states whether type-only imports count.
  - cargo-shear replaces `check_unused_crates.py`; knip replaces the in-house unused-code checker and its snapshot, and the user's rules of 2026-10-02 (a new unused name fails; a kept entry names its bead) stay as its shrink-only ratchet (2.1-E2), read with knip's definition of unused: an exported type used only in its own file's exported signatures is not unused (2.1-Q215).
- **Tests go through public surfaces.** Tests that read private fields or assert source text are shrink-only ratchets from Phase 0; each is rewritten by the stream that moves its module, and Phase 0 rewrites those whose module no stream moves (2.1-M20). A unit test sits beside its module; `src/__tests__/` holds cross-module suites only, and existing files leave it through a ratchet (2.1-E3). A suite moves to the browser lane only where it asserts layout or real renderer and input behaviour.
- **Model-based tests.** Each written state machine with interleavings (the Session union and its write lane, pool lanes, display descriptors, LiDAR jobs against the SQLite CHECK, map lifetime) ships a command-sequence test against the real implementation: fast-check `fc.commands` with `fc.scheduler` in TS, its seeds fixed in the pre-commit gate and every required CI check, random but printed only in a non-blocking seed lane (each PR and nightly on `main`), each failing seed kept as a regression case or filed as a bead (2.1-M60, 2.1-M67).
  - A small synchronous union gets an exhaustive transition-table test. fast-check and proptest also cover geo, CRS and camera maths.
- **Faults and hostile input** (Q47). The model-based Session, Draft, user-DB and LiDAR suites also run over the fault seams (`DurableFs`, the Draft records' `IDBFactory`, and the library worker's OPFS pool, faulted with quota, a killed worker mid-transaction and eviction; a library file is claimed before it is written and the janitor sweeps unclaimed files at open, 2.1-M151): after any fault a reopen gives the last or previous acknowledged revision and no Draft is lost.
  - cargo-fuzz runs on `canopi-format` admission and chain and on the LiDAR and raster readers in a scheduled lane: no panic, always a typed refusal, each crash a corpus case and a test.
- **Diagrams** (Q47, 2.1-M58, 2.1-M165, 2.1-M192). `check_docs.py` holds the component diagram's layers, ranks and `(2.1)` marks equal to `policy/layers.json` (plain JSON, no node or cargo), and fails a missing `Model:` line, a path or crate unknown without `(2.1)`, a `(2.1)` on a built path, a class that is no type, a state diagram unequal to its `Enum:`, a cargo graph unequal to `Cargo.toml` (`tomllib`, `workspace = true`). Code conformance is dependency-cruiser's rule in the Frontend gate; F4 checks class fields against the bindings. Each phase close drops the markers of what it built.
- **Contract suites** (Q16) only where a fake carries behaviour or two real sides exist. The suite registry (`policy/suites.json`: suite id, sides, test path, checked to exist), a hand-edited source table, is their full list (2.1-M193).
- **Fakes record and inject; they never re-implement a runtime rule.** Where a fake would carry behaviour, the real code runs instead: the gallery replays transcripts at the Data library port (a freshness check replaces the LiDAR facade suite) and storage ports run their real browser adapter over an in-memory backend, the raster pool tests drive the real worker handler in process, and the reduced catalog fake is deleted for the real DuckDB reader.
- **Complexity** (Q14, 2.1-Q213). oxlint `complexity` and the file-size script's per-file entries (600 lines, every language, 2.1-Q243) hold hotspots: no file's count grows, and a file a phase splits gets a per-file target from its measured baseline. Clippy `cognitive_complexity` is denied at 25; `too_many_lines` is a shrink-only ratchet of item-level `#[expect]` counts, and split LiDAR files get targets when Phase 3 splits them. A ratcheted clippy lint is denied; today's sites are item-level `#[expect]` counted by the ratchet (2.1-M188).
- **Mutation** (Q15). A non-blocking, sharded job runs on every PR over the diff: cargo-mutants `--in-diff` per crate, and Stryker `--incremental` from a report cached on `main` with `--mutate` built from the diff, on the Node lane only (2.1-M60). Survivors show as PR annotations. A full per-area run closes each phase; each survivor becomes a test or a bead. There is no score ratchet. Slow LiDAR tests get small fixtures or an optimised test profile, not `mutants::skip`.
- **Updates** (Q17, 2.1-M57). Renovate runs weekly, grouped minor and patch per ecosystem, except one cross-ecosystem Tauri group (crates and npm packages, since `tauri build` refuses a mismatched major.minor) and one PR per release set (the Vitest family, the TypeScript pair); each major is its own PR; exact pins wait on the dependency dashboard until the user ticks them (2.1-Q220); `minimumReleaseAge` and weekly lockfile maintenance; security updates come at once. Renovate is the hosted app (2.1-Q219).
  - Advisories: an OSV scan over `Cargo.lock` and `package-lock.json`, because RustSec carries no Tauri advisory after 2022, and `npm audit signatures` in CI. A toolchain upgrade lands before the baselines it moves (2.1-Q141).
- **Upstream** (Q18). Each local workaround is a row in the upstream register (`policy/upstream.json`) with its pinning test, tagged at its site by `// upstream: W<n>`, a `# upstream: W<n>` TOML comment or, in JSON, a pointer in its row; an expected-fail marker (Vitest `it.fails`, Playwright `test.fail`) tagged with an open W row is exempt from the pre-push marker rule (2.1-M202, 2.1-M237). The agent drafts each report as a bead with a repro; the user posts or refuses it.
- **Coverage** (Q19). Floors count production files only; out-of-line test files are excluded, re-baselined once with both numbers named. A floor is never lowered for the same file set. The coverage exclusion globs are a named ratchet entry; a new exclusion or a re-measured floor needs a bead and a Q row, and its commit names both numbers.
- **Flakes** are found by repeat runs (Vitest `--repeats`) and Vitest shuffle, seeded like the model-based tests (random only in the seed lane); a flaky test is quarantined with an owner and a bead, and the quarantine list is empty at each phase close; every test needs an assertion.

## Alternatives rejected

- **Hand-written policy tests beside the new tools.** Two rule homes drift.
- **A contract suite for every fake.** Many fakes are type-checked stubs; their suites cannot fail.
- **A blocking mutation score.** Scores are noisy; a gate costs more than it finds.
- **A line-count cap per file.** It can be met without improving the design, and a cap on every file fails 109 today.
- **Checking the stopping rule once, at the end.** It could only accept or reject the work, not steer it.

## Consequences

- AGENTS.md's coverage-floor rule changed with this ADR. Each AGENTS.md, guide or `CONTEXT.md` line a change makes stale, a check's name included, is rewritten in that change (2.1-M20); Phase 4 D1 is a final consistency pass.
- tauri-specta, Sheriff, CodeScene and nextest are dropped.
